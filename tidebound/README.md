# Tidebound

A cozy harbor-town game by day and a short co-op defense game by night, built as a **Roblox experience**. Players raise tide creatures called Drifters, run a shared harbor, and defend it in squads when the tide rises.

This folder holds the full vertical slice: game code, config, tests, a companion backend, the revenue model and the launch documents.

## Tech decision

Tidebound targets Roblox, so the engine, accounts, servers, payments and moderation tools come from the platform. All game logic is Luau, synced into Roblox Studio with **Rojo 7.7.1**. Roblox servers are authoritative by design: the server owns currency, inventory, rolls, damage, rewards and timers, and clients only send intents. Saves use **DataStores** with session locking. Payments use **MarketplaceService** (Developer Products, Game Passes, Subscriptions), with `ProcessReceipt` as the server-side receipt check. Rules that do not touch the engine (economy, hatching, crate odds, the night simulation, the store ledger, the save migration) live in plain Luau modules under `src/Shared`. The server, the client and the test suite all run that same code. Tests run outside Roblox with **Lune 0.10.5**, which also runs the real server scripts against emulated engine services. A small **Node 22 + TypeScript** companion service covers what Roblox servers cannot do alone: the signed right-to-erasure webhook, opt-in notifications while players are offline, publishing live config, and support reversals, all through Roblox Open Cloud.

## Layout

| Path | What it is |
| --- | --- |
| `shared/config/*.json` | Every tunable value (cycle, day loop, economy, Drifters, night, harbor, catalog and pricing, compliance). Baked into the place as safe defaults; live overrides come from remote config. |
| `shared/schemas/` | JSON Schemas for each config file (generated by `shared/tools/gen-schemas.py`). |
| `src/Shared/` | Engine-independent Luau: rules, odds, store, night simulation, save schema and migrations, revenue math. |
| `src/Server/` | Roblox server services: data, config, store, night rooms, harbor, social, account, analytics, debug (development builds only). |
| `src/Client/` | Roblox client: HUD, every panel, onboarding, night renderer and controls, quick chat. |
| `src/Localization/strings.csv` | English string table (543 keys), generated by `shared/tools/gen-strings.py`. |
| `backend/` | Companion service (Open Cloud integrations, KPI events). |
| `model/` | Revenue model: `revenue-model.xlsx` (live formulas) and `revenue-model.html` (calculator), both built from `catalog.json`. |
| `tests/` | Lune test runner, specs, the Roblox runtime harness, and tools. |
| `docs/` | Setup, balance, pricing, security, store readiness, roadmap, KPI dashboard, privacy and terms templates, data inventory, assets. |

## Run it

```bash
aftman install                     # rojo, lune, stylua, selene (see aftman.toml)
lune run tests/run                 # 65 specs: rules, odds (100,000 rolls), balance, store, night, server integration
rojo serve                         # live-sync into Roblox Studio (default.project.json, includes the debug panel)
rojo build release.project.json -o Tidebound.rbxl   # release place, debug panel removed
cd backend && npm ci && npm test   # companion service
python3 model/build_model.py       # rebuild the revenue model from config
```

Full setup, including Creator Hub products, secrets and the backend, is in [docs/SETUP.md](docs/SETUP.md).

## Assumptions

- The brief targeted iOS and Android with Unity; it changed to Roblox mid-build. Platform features now use their Roblox equivalents. The table at the end of this section lists each mapping.
- Roblox accounts replace guest accounts and Apple, Google or email linking. Progress follows the Roblox account on every device.
- No in-game age gate. Roblox forbids collecting age data in experiences and enforces age, chat and spending rules at the account level (Parental Controls). The game respects `PolicyService` and adds its own monthly spend limit.
- Robux prices follow the brief's rule (USD ÷ 0.01). Live prices shown to players come from Roblox, so the screen always matches the charge.
- Harbor Club uses Roblox Subscriptions (priced in local currency by Roblox). Starter Pack and Storage Pass are Game Passes. Gems, crates and the Harbor Pass are Developer Products.
- A Harbor Pass "season block" is 4 weekly seasons (28 days) with 30 tiers.
- Storage is capped at 200 for everyone. Paid storage reaches that cap sooner; it never goes past it.
- Waves last 42 s with 9 s breaks and a 3 s intro, so six waves fit the 5-minute night.
- Enemy health grows 8% per wave, compounding.
- The streak bonus counts the night just survived: the first survived night pays +5%, capped at +30%.
- The tuned enemy base count is 3 (formula unchanged). With 4, a brand-new solo player usually lost at wave 5; with 3, a level-4 Guardian survives solo.
- One Roblox server is one night room: up to 4 squads of 5. MaxPlayers should be 20.
- Every night has The Undertow in wave 6, except the tutorial night. Pearls come from boss defeats and level milestones.
- Players who leave mid-night keep rewards for finished waves at full rate. Their streak is unchanged.
- The rewarded-ad placement is wired up behind its config flag, which is off.
- Duplicate crate items convert to Gems at a fixed rate per rarity.
- A reversed purchase removes what it granted. If the Gems or Silver were already spent, the shortfall becomes debt that future grants repay. Drifters are never removed.
- Raising the monthly spend limit waits 24 hours; lowering it applies at once.
- Notifications go out through Roblox experience notifications (opt-in), at most 2 a day, never between 21:00 and 08:00.

| Brief item | Roblox implementation |
| --- | --- |
| Unity client, URP, Input System, Addressables, TMP | Roblox client in Luau; ContextActionService (touch, keyboard, gamepad); named assets in `ReplicatedStorage.Assets` with placeholder fallbacks |
| PlayFab / Firebase / Nakama backend | Roblox servers + DataStores + MessagingService + Open Cloud; small companion service |
| Apple / Google receipt validation | `ProcessReceipt` (Roblox validates payment), game pass and subscription status reads |
| Store fees 15% | Roblox payout: 30% fee, DevEx $0.0038 per Robux (developer keeps 26.6%) |
| Guest accounts with linking | Roblox accounts |
| Age gate and parental consent | Roblox account age, Parental Controls and PolicyService; in-game spend limit |
| Push notifications | Roblox experience notifications |
| Crash reporting | `ScriptContext.Error` on server and client to structured logs and the backend |

## Acceptance checklist

| Criterion | Status | Evidence |
| --- | --- | --- |
| New player: onboarding, full day, squad night, leave, return with progress intact | Passes in tests | `tests/specs/server.spec.luau` runs the real server code: tutorial, tutorial night, a 3-player squad surviving all 6 waves, leaving, and rejoining on a second server. `lifecycle.spec.luau` covers 12 hours offline with the 8-hour cap. |
| Every product bought, validated, granted once, refunded | Passes in tests | `server_store.spec.luau`: every Developer Product through `ProcessReceipt` with retries, rollback on failed save, audit log, support reversal; game pass revocation; subscription status. `store.spec.luau` covers every product's ledger. |
| Odds and pity shown match server behavior (100,000 rolls) | Passes in tests | `odds.spec.luau`: 100,000 hatches and 100,000 crates; every rarity within 4 standard errors of the displayed overall rate; pity never exceeded. |
| No product increases power, drop rates or rewards | Passes in tests | `store.spec.luau` "Fairness" buys everything and compares power, income, slots and odds. `ConfigValidator` rejects configs that sell gameplay rewards. |
| Config changes change the game and the revenue model without code edits | Passes in tests | Live config push in `server_store.spec.luau`; Robux price, bundle size and buy-rate changes in `store.spec.luau` and `revenue.spec.luau`; the model rebuilds from `catalog.json`. |
| Revenue model reproduces the planning numbers | Passes | `model/check_model.mjs`, `revenue.spec.luau`, and the Model sheet's planning check rows |
| Age gate, spending controls, account deletion, quick-phrase chat | Passes in tests (age gate replaced) | Spend limit and policy checks, export and deletion, and phrase-only chat in `server_store.spec.luau` |
| 60 FPS on a mid-range phone during a full night | Not yet measured | Designed for it (no server physics for enemies, pooled anchored parts, 20 Hz snapshots, one sector rendered). Needs a device test; see ROADMAP week 1. |
